## 能做什么

| | |
|---|---|
| **智能选格式** | PNG → WebP（保留透明，通常直接减半）；其余 → JPG |
| **目标体积** | 填 200 KB，它会在质量区间里二分搜索，刚好压到目标以下 |
| **限制最长边** | 4K / 2K / 1920 / 1280 / 800 或保持原尺寸 |
| **透明转 JPG** | 检测到 alpha 会先垫白底再合成，不会变成一团黑 |
| **批量** | 多选、拖拽、Ctrl+V 粘贴都行，队列逐张处理 |
| **前后对比** | 可拖动分割线对比，并列出当前设置下 JPG / WebP / PNG 三种格式的体积 |

## 三个容易做错的细节

**WebP 支持是「验证」而不是「假设」。** Safari 曾经接受 `toBlob(..., 'image/webp')` 却悄悄返回 PNG。
所以这里会编码一个 1×1 测试像素并检查 `blob.type`，不是真 WebP 就回退 JPG，不会产出一个改错后缀的文件。

**EXIF 方向在解码时烘焙。** `createImageBitmap(file, { imageOrientation: 'from-image' })` 在解码阶段
就把旋转应用掉，手机竖拍的照片不会变成横的——有些浏览器把 `<img>` 直接画进 canvas 时就会踩这个坑。

**目标体积用二分搜索质量**，不是猜一次：在 0.05~0.95 之间迭代 8 次，区间窄于 0.04 就提前收敛。
即使最低质量仍然超标，也会在该行明说「已压到最低质量，仍略大于目标体积」，不假装达标。

## 怎么用

下载 `index.html` 双击打开。不用安装、不用构建、不用联网。

## 注意

- PNG 重新编码几乎不减体积。没有透明通道的 PNG，行内会提示改用 WebP 或 JPG。
- 输出受浏览器编码器能力限制；照片一般质量 75 就是不错的默认值。
- 动图 GIF 只压缩第一帧。
